FAQ

The twelve questions people ask before using it

Where the photo goes, which files it opens, how exact the LUTs are, whether it still works without a connection — answered from what is actually implemented, including what it does not do.

Updated 2026-11-196 min read

This page answers the twelve questions that come up before using it: whether photos are uploaded, which RAW files it opens, what size the LUTs are, whether it works offline, what export produces and whether it runs on a phone. The answers describe what is actually implemented, including what it cannot do.

To see how it works first, read opening a RAW in the browser; to compare it with desktop software, read the Lightroom comparison.

Questions and answers

Does it upload my photos?

No. RAW decoding runs in a Web Worker on this machine, development and rendering happen on the GPU, and files are only read locally — there is no upload endpoint. The only network requests are the app's own assets and an /api/geo country lookup used to choose the initial interface language. There is no account system and no analytics or tracking cookies; the privacy note has the details.

Which RAW formats can it open?

NEF / NRW (including HE and HE* compression), CR2, CR3, ARW, SRF, SR2, DNG, RAF, ORF, RW2, PEF, SRW, 3FR, ERF, KDC, MOS, IIQ and X3F. It also opens JPEG, PNG, WebP, AVIF, HEIC/HEIF and TIFF. If a RAW cannot be unpacked at all, the camera JPEG embedded in the file is used instead of showing half a black frame.

Is it really free, and under what license?

Yes, and there is no sign-up. The code is MIT-licensed and published on GitHub, so you can read it or deploy your own copy. There is no subscription and no paid tier.

What is a LUT, and what size are the built-in ones?

A LUT is a look-up table mapping input colour to output colour: a grade frozen into data, so applying it is faster and more portable than recreating a series of slider moves. The 64 built-in looks ship as a 33×33×33 pack — 33 steps per channel, 35,937 entries — which is exact against the authored recipes. Smaller sizes were measured too: 17³ has a mean error of 0.226 levels out of 255 (maximum 20.8), 21³ a mean of 0.182 (max 11.6), 25³ a mean of 0.128 (max 11.3); going up to 65³ would multiply the storage for no visible gain. The full list is in the look catalogue.

Can I import my own .cube files?

Yes. 3D LUTs (LUT_3D_SIZE 2–128) and 1D LUTs are supported; 1D tables are baked onto a 3D grid, and a UTF-8 BOM is tolerated. Files are parsed locally and never uploaded, and they appear under “My LUTs”, where they survive a reload.

What are the dual-LUT and merge features for?

The two slots each hold a look with its own strength — a cool film base under a light warm highlight tint, for example. When the stack looks right, merge bakes both layers into one 33³ LUT using the same rule the renderer uses, mix(v, lut(v), strength) per slot, saves it under My LUTs and downloads it as a .cube (35,937 rows) that works in Premiere, Resolve or any other .cube-capable app.

Why do vendor LUTs need F-Log or V-Log?

Vendor LUTs from Fujifilm, Panasonic and others are built for a log-encoded image: the input is not a normal display picture but a signal that packs highlights into a code range, so applying one directly to an sRGB image shifts colours. The app has sRGB, F-Log, F-Log2 and V-Log input profiles: choose the matching one and the frame is re-encoded with the published transfer function before the LUT runs. A LUT whose name carries F-Log or V-Log is detected automatically. Gamut is still treated as sRGB, so results are close but not byte-exact. The RAW-in-browser guide covers the pipeline in detail.

What does export give me?

A JPEG at 50 / 75 / 100 % of the source long edge, at quality 0.90 / 0.95 / 0.98 respectively. The 100 % option renders the in-memory full-resolution frame in tiles, so it can go past the GPU texture limit instead of quietly downscaling. The export includes the development and the LUT; there is no TIFF or DNG output.

Does it work on a phone?

Yes. The editor has a narrow-screen layout and runs in a phone browser that supports WebGL2; if the device or browser does not support WebGL2, the editor cannot render. Keyboard shortcuts do not apply on a phone — switching looks and exporting are on-screen controls. The interface is Chinese and English, auto-selected by country and switchable from the toolbar.

Does it work offline?

There is no offline-mode switch, so what happens depends on the browser cache. The first visit needs a connection to load the app assets, and the first RAW open downloads about 3.4 MB of decoder. Once those resources are committed to the browser cache, reopening the page without a connection will usually still load — provided the cache has not been cleared. After a cache clear, or on a different browser or device, they have to be downloaded again.

Is there a library or a batch mode?

No. This is a single-frame editor: one photo at a time, with no catalogue, ratings, keywords, batch queue or sync. For batch processing or a long-term library, desktop software is the right category; the Lightroom comparison explains where this tool stops.

Where do imported LUTs get stored?

In the browser's IndexedDB, under “My LUTs”; merged LUTs are kept in the same place, and interface preferences live in localStorage. They are not uploaded and do not sync between devices. Clearing site data removes them, so download a .cube if you want to keep a merged look.
