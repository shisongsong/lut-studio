A LUT is a colour table, not a filter

A look-up table takes a colour in and returns another colour out. A 1D table and a 3D table can do very different things, and vendor LUTs assume log-encoded input — get that precondition wrong and the image turns dark, harsh and off-colour.

Updated 2026-11-197 min read

A table: colours go in, colours come out

A 3D LUT is a cube of data. Each axis is an RGB channel running from 0 to 1, the edge n says how many nodes each channel is cut into, so the table holds n³ nodes. To render a pixel, its RGB is located inside the cube, the eight surrounding nodes are read, and trilinear interpolation produces a new RGB. It does not touch structure or sharpness — it only moves colours around.

The interchange format is .cube, plain text:

TITLE "Cream Highlight"
LUT_3D_SIZE 33
DOMAIN_MIN 0 0 0
DOMAIN_MAX 1 1 1
0.07830 0.07540 0.07112
…

LUT_3D_SIZE 33 means an edge of 33, so the file must contain 35,937 rows of RGB values; DOMAIN_MIN / DOMAIN_MAX declare the input range, normally 0–1. Rows are ordered with R changing fastest, then G, then B. A 1D LUT uses LUT_1D_SIZE and stores far fewer rows — n rows of RGB, one curve per channel.

This editor imports 3D LUTs (LUT_3D_SIZE 2–128) and 1D LUTs, parsing the file locally: a .cube is text, possibly with a UTF-8 BOM; it is stored in the browser’s IndexedDB and never sent anywhere (the details are in the privacy note). A 1D file is baked onto a 33³ grid so the renderer only ever deals with one kind of data.

1D versus 3D

Dataone curve per channel, n samples eachn³ RGB triplets, 35,937 at 33³
Lookupeach channel maps alone: f(R), g(G), h(B)all three channels index the cube, then trilinear interpolation
Can doblack point, white point, gamma, per-channel shiftsany colour mapping: hue rotation, desaturation, film-style cross-talk, gamut compression
Cannot docross-channel effects: pull one hue only, convert colour to monochromeadd information; values between nodes are still interpolated

The decisive difference is whether channels can influence each other. A 1D LUT evaluates R, G and B separately, so the red channel never consults green. The cross-talk of film — red drifting towards cyan, warm blue highlights — and a genuine black-and-white conversion that redistributes all three channels by luminance both need a 3D table. That is why all 64 built-in looks are 33³ cubes, and why the precision measurement measures 3D cubes.

Why vendor LUTs want log input — and what sRGB does to them

Log encoding spreads scene brightness out: it lifts the shadows so that the 0–1 code range holds far more dynamic range than a display, instead of following display contrast the way sRGB does. The F-Log, F-Log2 and V-Log LUTs published by camera makers are designed for input already encoded with that curve — every input code value corresponds to a specific scene luminance.

An ordinary photograph is display-encoded sRGB. The same shadow detail sits at a far higher code value in log than it does in sRGB. Feed the sRGB value to a log LUT and you are telling it “this shadow is far darker than it is”, so the result comes out dark and crushed, and colours drift or oversaturate because every lookup happens at the wrong place in the cube. The LUT is not broken; its input precondition is not met.

This editor has an input colour space setting in front of the LUT: sRGB, F-Log, F-Log2, V-Log. With a log profile selected it converts the display value back to linear, re-encodes it with the published transfer function, and only then samples the table; when an imported .cube has F-Log or V-Log in its name or title, the setting switches automatically. Gamut is still treated as sRGB, so vendor LUTs land close but not byte-exact.

What the strength slider actually mixes

The grading step is mix(v, lut(v), strength). At 0 the output equals the input, at 100 it equals the table’s output, and in between it is a straight line between the two values. It does not shrink the LUT’s parameters; it blends the original image and the graded image in proportion.

So a heavy look at 50 % does not become a gentler look — it becomes half original colour and half style: contrast is diluted and saturation looks flatter. This is also why the editor suggests 30–60 % when a vendor log LUT is used on an ordinary photo: take a small dose of the look, and do not expect a table designed for log to behave as an sRGB grade.

When two looks are stacked, each layer mixes once and A’s output becomes B’s input; that order and blend are baked verbatim into a merged .cube — see merging LUTs.

A LUT cannot bring clipped highlights back

A LUT is a per-pixel colour swap: it reads an existing RGB and returns another RGB. If all three channels of a pixel are pinned at 1.0, the table can only map that to some fixed output value — every fully clipped highlight collapses to one colour, so the sky gradient or the lamp edge that used to be there is gone. The same applies when a single channel is clipped in a badly white-balanced shot: once it is clipped, that channel’s information is not there to recover. Lookup inputs are also clamped to 0–1, so values above 1 are not even considered at the LUT stage.

That is why this editor runs the whole RAW pipeline first: the RAW is decoded at 16 bits with four stops of scene headroom above white, and the display transform uses darktable’s sigmoid — monotone on 0…∞ and asymptotic to the white target rather than clipping, so highlights are compressed into the visible range instead of cut off. Only after development and the display transform does the LUT take over. The processing order is described in opening a RAW in the browser.

Where the LUT sits in this editor’s pipeline

  1. Decode and develop. The RAW becomes a 16-bit scene-linear frame in a Web Worker; exposure, white balance, highlights and shadows act in linear space, with the real above-white data still present.
  2. Display transform. Sigmoid compresses scene-linear into 0–1 display values, monotone and without clipping.
  3. Input colour space (optional). For vendor log LUTs, the display value is re-encoded with the matching log curve.
  4. LUT. Slot A mixes by strength; with dual LUTs enabled, slot B follows. Both run mix(v, lut(v), s).
  5. Export. JPEG at 50 / 75 / 100 % of the source long edge, from the same pipeline the screen uses.
