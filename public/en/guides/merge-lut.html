Bake two LUTs into one and take it out of the browser

The editor can stack two looks: A underneath, B on top of A’s output, each with its own strength. Press MERGE and the whole stack is baked into one 33³ .cube, saved under My LUTs and downloaded to your machine.

Updated 2026-11-195 min read

Why bake two LUTs into one

The obvious reason is hand-off. A LUT slot in Resolve, Premiere or Photoshop takes one table at a time. Bake the A + B stack into a single .cube and the other person only has to load one file to get the grade you built — no explanation of which two looks were used or how strong each one was.

The second reason is keeping the grade. The merged look lands under My LUTs next to your imported .cube files, and from there it behaves like any other look: you can select it, stack it, and it is still there after a reload. It is effectively a freeze button for the current stack.

The third reason is consistency. The bake runs the same composition the renderer runs; it is not a second approximation, so no second colour model creeps in between the screen and the file.

What the bake actually computes

Each slot performs one strength-weighted blend, A first and B second:

v = input colour
for slot in [A, B]:
  s = strength / 100
  t = trilinear_sample(slot.lut, v)
  v = v + (t - v) * s        // that is mix(v, lut(v), s)
output = clamp(v, 0, 1)

That is exactly the shader’s applyLut: mix(c, texture(lut, clamp(c,0,1)).rgb, s). The merge runs the same loop over every node of a 33³ grid and writes a new 33³ cube. Source cubes are read with trilinear interpolation, and the output is quantised to 1/255 per channel — the same precision as the LUT texture in the browser.

If both strengths are at 100 %, a host app that renders the downloaded .cube at 100 % strength reproduces the screen: same formula, same node grid, same quantisation. The LUT precision measurement explains why 33³ is the authored size for these looks.

What is in the exported .cube

The file is plain text: four header lines and 35,937 rows of RGB values.

TITLE "A + B"
LUT_3D_SIZE 33
DOMAIN_MIN 0 0 0
DOMAIN_MAX 1 1 1
0.07830 0.07540 0.07112
…

TITLE carries a name such as “A + B”, LUT_3D_SIZE 33 tells the host app the edge length, and DOMAIN_MIN / DOMAIN_MAX declare a 0–1 input range. Rows are ordered with R fastest, then G, then B, three five-decimal numbers per line. A 33³ .cube is a few hundred KB of text — each built-in look in the repository is around 840 KB.

The order is part of the grade

A then B is not the same as B then A: B’s input is whatever A produced, so swapping the slots changes the colours it is asked to map. Two layers at 50% are not an average of two LUTs either — each layer mixes against the output of the previous one, so the colour is pushed twice and in a different direction.

Set the strengths before you merge, because the bake freezes the current state rather than making choices for you. If you want the other order, swap the slots and merge again.

Can a merged LUT be used again?

Yes. It appears in the My LUTs category and can be picked as A or B for another stack. Merging a single look works too: that is how you export one built-in look as a .cube without turning on dual mode.

Keep in mind that every merge re-quantises its output to 8 bits. With three looks, merge the first two, then merge that result with the third, rather than repeatedly re-baking intermediate files — each pass accumulates a little more rounding, even when it is small.

Using it in Resolve, Premiere or Photoshop

Load the downloaded .cube into a LUT slot: a colour node in Resolve, Lumetri in Premiere, a Color Lookup layer in Photoshop — all of them read this format. Set strength to 100 %. The strengths of A and B are already baked into the numbers; pulling the host slider down just flattens a grade that is already finished.

One more thing has to match: the cube was baked in display-encoded sRGB space, so feed it display-encoded footage. LOG footage such as F-Log or V-Log needs an input transform first, for the same reason vendor LOG LUTs do — that is covered in what a LUT is. It is also why this editor runs a whole 16-bit RAW development pipeline and puts the LUT after the display transform.

Open the editor, drop a photo in, pick two looks, set the strengths and press merge — that is your first .cube.
