GUIDES

Take a photo from RAW to JPEG

These articles describe how this browser darkroom actually works: where the RAW is decoded, what the 16-bit linear pipeline preserves, how precise a LUT has to be, and how two looks are baked into one .cube. No marketing, just reproducible steps and measured numbers.

Updated 2026-11-19

Read them in order or use them as a manual — each page follows the same structure in Chinese and English.

  • GUIDE · INSTALL A LUT

    Where a LUT actually goes, app by app

    The same .cube lives in a different place in every app — and a creative look goes somewhere different from a LOG conversion LUT. This page lists the menu paths, the folders and the usual traps; if you want to see the result first, preview it in the browser instead of installing anything.

  • GUIDE · LUT PRECISION

    How precise does a LUT have to be before the difference disappears

    A LUT’s precision is its cube edge: 17³ holds 4,913 nodes, 33³ holds 35,937. We ran one photo-derived query set through four sizes, and the answer is not “bigger is better” — it is “match the cube the look was authored on”.

  • GUIDE · MERGE LUTS

    Bake two LUTs into one and take it out of the browser

    The editor can stack two looks: A underneath, B on top of A’s output, each with its own strength. Press MERGE and the whole stack is baked into one 33³ .cube, saved under My LUTs and downloaded to your machine.

  • GUIDE · RAW

    Open a RAW in the browser and develop it like a darkroom

    NEF, CR2, CR3, ARW, DNG and RAF files can be dropped straight into the browser window. Decoding, developing, grading and exporting all happen on this machine — the photo is never uploaded.

  • GUIDE · LUT BASICS

    A LUT is a colour table, not a filter

    A look-up table takes a colour in and returns another colour out. A 1D table and a 3D table can do very different things, and vendor LUTs assume log-encoded input — get that precondition wrong and the image turns dark, harsh and off-colour.
