Open a RAW in the browser and develop it like a darkroom

NEF, CR2, CR3, ARW, DNG and RAF files can be dropped straight into the browser window. Decoding, developing, grading and exporting all happen on this machine — the photo is never uploaded.

Updated 2026-11-206 min read

Why a browser can develop a RAW

RAW processing is a numeric pipeline: unpack, demosaic, white balance, colour matrix, tone map, output. None of that requires a desktop app. A modern browser brings the two capabilities that matter — WebAssembly for the heavy decoding, WebGL2 for mapping 16-bit scene-linear data to the screen at interactive speed.

LUT ARCHIVE compiles flashraw to WebAssembly and runs unpacking, AHD demosaicing, camera white balance and the camera colour matrix in a Web Worker. The decode keeps 16 bits and four stops of scene headroom above white, then re-encodes the frame as scene-linear half floats for the GPU. That headroom is why the highlights slider behaves like a raw processor rather than a JPEG editor: it compresses real above-white sensor data back into visible gradation instead of darkening pixels that were clipped before it ever saw them.

The display transform is darktable's sigmoid (jandren, merged for darktable 4.2): monotone on 0…∞, asymptotic to the white target instead of clipping, with parameters fitted in closed form. npm run test:tone:reference uses an isolated darktable 5.6.2 CLI to render a synthetic 128×512 linear EV ramp to a 16-bit PNG and compare decoded pixels; the observed maximum linear-light error is 0.0014772 (test limit 0.0016). This validates the sigmoid curve, not a full camera RAW decode or Lightroom's Auto algorithm.

Opening a RAW also applies a camera look by default: the luminance percentiles of the camera JPEG embedded in the file are matched against the neutral render, and one monotone display curve is fitted, together with the camera JPEG's mean chroma and RGB balance for saturation and white balance, so the photo opens close to the phone gallery / camera rendition. One click in the Develop header returns to the neutral development. The reference lives inside the RAW file, so no screenshots are needed.

RAW highlights and shadows act in two layers: a blurred luminance guide decides where the exposure-style change applies, and a multiscale Local Laplacian refinement is added on top. A Worker builds a roughly 320px scene-EV map, creates monotone remap pyramids at evenly spaced intensity references, and combines them with tent weights; the GPU adds that EV map at 45 % weight as a luminance ratio to the full-resolution linear RAW before sigmoid. The LLF term is deliberately not the whole response: measured on the night reference it moved the brightest 1 % of pixels by only about 0.5 EV (small bright regions are edges to the pyramid), so using it alone made the Highlights slider read as broken. The slider mapping is an engineering design, not Adobe's internal parameterization; Auto Tone remains a separate percentile heuristic, not a claimed Lightroom Auto clone. With the camera look on, Auto Tone keeps the camera exposure, uses the neutral-calibration result only as a one-way placement hint (open/brighten allowed, darkening not), and solves the shadows/highlights/whites/blacks sliders against the actual with-look rendered histogram; with the look off the calibrated neutral heuristic is unchanged.

If a RAW cannot be unpacked at all, the app falls back to the camera JPEG embedded in the file — including 45 MP-class bodies whose frames the decoder returns truncated. That beats showing half a black frame, and it beats failing outright.

One pass through the app

  1. Drop the file in. Unpacking, demosaicing and preview generation each show a named stage with a live clock instead of a fake animation.
  2. Check the auto exposure. For RAW it is computed in the scene domain: the 95th percentile sits near sensor white and midtones stay below about 0.39 of white, so a dim interior comes out lit instead of muddy. The AUTO button turns it off.
  3. Develop. White balance and exposure operate in linear light; RAW highlights/shadows pick their range from a blurred luminance guide and add a Local Laplacian refinement, while whites/blacks adjust the displayed endpoints. The eyedropper picks a neutral, and preview/export share the same pipeline.
  4. Apply a look. 64 built-in looks with adjustable strength, a second slot for stacking, and local .cube import that survives a reload in IndexedDB.
  5. Export. JPEG at 50 / 75 / 100 % of the source long edge; 100 % renders the in-memory full-resolution frame in tiles, past the GPU texture limit.

What it does not do

This is a single-frame darkroom, not an asset manager: no library, no batch sync, no cloud catalogue, no AI masks. The preview is capped at 4096 px on the long edge because pushing a 20 MP+ linear frame to the GPU wholesale is both slow and memory-hungry; export is not capped. The first RAW you open downloads about 3.4 MB of decoder, cached afterwards.

If you need a full post-production workflow — catalogues, batch processing, printing — desktop software is still the right tool. If you want to take one RAW, develop it to taste and leave with a full-resolution JPEG on whatever machine you are on, the browser is enough.
